# Crate v0.4.1

Patch release: background lyrics backfill and orphaned `.lrc` cleanup, each behind
its own opt-in setting (Ajustes → Reproducción → Letras), both off by default.

## Highlights

### Background lyrics
- New **Descargar letras en segundo plano** toggle. When enabled, the app fetches
  missing lyrics from LRCLIB in the background — for songs as they are added to the
  library, plus a one-time sweep of the existing library on startup — without
  needing to play the track. Distinct from the existing on-playback auto-fetch.
- Candidates are limited to tracks with no lyrics anywhere (`shouldBackfill`): a
  track that already has a `.lrc` sidecar or embedded tags is never touched, so no
  redundant sidecars are written.
- Implemented as `LyricsBackfillService` with a small in-memory queue, bounded
  concurrency, and a per-fetch gap that drips requests (on top of the LRCLIB
  provider's own rate limiting). The toggle is honored at drain time, so turning it
  off stops network activity immediately; turning it back on resumes the sweep.

### Orphaned `.lrc` cleanup
- New **Eliminar archivos .lrc huérfanos** toggle. When enabled, library scans
  delete `.lrc` sidecar files whose matching audio (same basename, any recognized
  audio extension) no longer exists — covering both sidecars of removed songs and
  pre-existing stray `.lrc` files. Embedded lyrics are out of scope.
- Safe by construction: gated and off by default, best-effort (never aborts a
  scan), only operates inside library roots, and never deletes a `.lrc` whose
  sibling audio is present (`isOrphanLrc`).
- Deletions are recorded in the library scan log as a new
  `orphan_lrc_removed` event ("Letra huérfana eliminada").
